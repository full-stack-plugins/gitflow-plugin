# GitFlow 分支治理与 git-skills 首版契约

状态：首版契约 R01–R18 已实现，后续按用户授权完成源码与 v0.1.2 发行。当前 v0.1.5 增量 R19–R25 完成实现与本地 91 项验证，远端 CI 按发布 commit 查验；实际宿主事件接线与托管保护仍未验证。

## 范围

技能包独立维护 git-awesome、git-workflow、git-init、git-branch、git-audit、git-commit、git-sync、git-release、git-recovery。插件提供标准库 CLI、stdio MCP、Claude-shape Hooks、可移植 Agent Plugins 1.0.0 包及宿主兼容清单。支持本地 macOS/Linux Git 仓库、linked worktree、普通远端与本地 bare 远端测试。不安装到用户宿主；后续源码提交、推送与发行遵循已有用户授权。

## 验收要求

R01：权威流程目录包含 Classic Git Flow、GitHub Flow、GitLab 环境/发布模型、主干开发、Microsoft Release Flow、Git 维护者模型，以及集中式/Fork 协作模型；来源、核验日期、适用条件、冲突、扩展规则标识明确。
R02：九技能均有精确触发描述、独立使用路径、前置条件、授权边界、步骤、验证、异常与正反例；引用不依赖兄弟技能安装。
R03：discover 只读识别真实根、Git/common/worktree 目录、HEAD/unborn/detached、分支/远端、dirty、冲突/merge/rebase；显式 discover/context 在无 Git 时返回明确上下文与初始化问题，不默默初始化；自动触发条件以 R19 为准。
R04：init 默认预览；显式 apply 落地 JSON 定义与生成说明，显式 initialize_git 才初始化无 Git 项目。已有仓库默认要求选定 profile 或既有契约；空仓采用团队 Classic Git Flow 默认。不得覆盖既有规范；幂等重复不改写。
R05：共享模式 .gitflow/workflow.json 为定义；所有插件项目数据统一放在工作树根目录 .gitflow/，生效快照、来源、运行时和日志放在不提交的 .gitflow/state/。local 模式仅写该本机状态，不写共享定义，clone 不共享。多个 worktree 共享生效规则与来源，各自隔离日志；Git 目录只保留原生 hooks、定位配置与 ignore 配置。
R06：严格闭合、限长的工作流结构；角色、命名、创建来源、合入目标、提交、合并策略、远端、提交消息与例外均校验。激活记录绑定已确认定义；候选漂移不能自动弱化规则。规范更改默认预览、显式 activate 才生效。
R07：audit 只读检查长期角色覆盖、已有分支角色/命名及当前操作状态；临时分支无任务时不要求存在。无历史来源只标未知，不能以 merge-base 断言创建来源。远端跟踪记录不当作实时远端。
R08：branch create 校验 Git 名称、项目角色、来源、冲突与 worktree 占用；默认预览、apply 执行并记录来源 OID。switch/rename/delete 保留 dirty，拒绝未合入删除与保护分支变更。reconcile 只补缺失长期分支，不自动首提交。
R09：gate 校验 commit/push/merge/rebase 等动作的真实源与目标身份、命名、角色、规则修订与状态；日常提交禁止保护分支。消息可按项目配置验证。GitFlow 分支批准不是 CodeGuard 质量批准。
R10：sync fetch/pull/push/merge/rebase 默认预览；显式 apply 执行，固定目标与前后 Git 身份。未建模的 force、删除/多 ref 推送拒绝。上游/远端目标不能猜测。不修改凭据，不外发仓库内容给模型。
R11：release/hotfix start 按规则记录基线；finish 形成逐目标集成计划，执行已授权步骤并追踪未完成回灌；不擅自推送发布、不因只有一个 merge 就完成。Microsoft/Git-maintainer 原则独立，不混为通用规则。
R12：recovery 只读诊断 wrong-branch、冲突和中断；安全迁移未提交修改、保留原引用的错分支提交迁移、abort/continue 都必须显式 apply；无 reset --hard、强推或自动 stash 丢弃。
R13：原生 Hook 与宿主 Hook 提供注入/检查；SessionStart/Prompt/Stop 有界摘要，PreToolUse 识别当前 cwd、git -C、简单 cd && 链以及受管 Git 子命令，未知动态语义返回未验证；不误拦 help 文本。PostToolUse 刷新观察。Hook 故障不报告 PASS。
R14：显式 context 调用的无 Git 回答可记录初始化/暂不启用决定；自动 Hook 在无 Git 时保持静默，状态变化重新发现。确认记录不是 Git 写入操作的授权。
R15：MCP initialize/list/call 用真实 stdio 握手验证；读工具标记只读，写工具显式 apply，参数闭合。退出码 0 为本动作合规/完成，1 明确违规，2 用法错误，3 未验证，4 内部错误；报告保持 schema/action/decision/reasons/next_actions。
R16：变更日志按 repo/worktree 分隔、原子写入与互斥；每步记录 before/after，失败或外部超时读取实际状态，unknown 不当作失败或成功；恢复不重复创建提交。
R17：锁定技能与模板快照及摘要；校验篡改与包路径；标准 manifest/MCP Schema 与真实包运行独立验收。
R18：9 技能校验、TRACE、真实临时 Git 场景、CLI/MCP/Hook、打包后异 cwd 调用、完整回归通过；实际宿主安装、远端 CI、公开发行未执行时明确未验证。

## 技术与非目标

Python 3.11+，Git 2.41+，无运行时第三方依赖。策略采用 JSON，避免要求项目安装 YAML 库；Markdown 是生成说明。不初始化 Spec Kit/OpenSpec，不修改其他仓库，不强行迁移已有分支历史，不声称本地 Hook 能约束全部终端或服务端操作。发布、源码 Git init、提交推送和宿主安装需对应授权。

## 2026-10-07 增量：仅 Git 项目自动触发

R19：自动 Hook 只在真实 Git 工作树中注入上下文或参与 Git 动作门禁。使用 argv Git 的 rev-parse 检测，支持仓库子目录、unborn、detached、linked worktree 与子模块；普通目录和 bare 仓库输出空 JSON，不提示初始化、不记录无 Git 决定、不创建文件。宿主 payload 缺少 cwd 时不得退回插件运行目录。每次事件重新检测，不缓存先前状态；同一会话先 git init 后启用，移除 Git 管理后停用。
R20：PreToolUse 按 git -C（含紧凑形式）及简单 cd && 的实际目标工作树判断；从无 Git 目录指向 Git 仓库仍检查，从 Git 仓库指向普通目录保持静默；无 Git 项目中的动态/未知命令不得凭空激活。损坏或不可读的 Git 元数据不等同普通目录，返回未验证提示，不伪造允许；检测不执行输入命令，不受 GIT_DIR/GIT_WORK_TREE 等环境误导。
R21：保留显式 CLI/MCP discover、context、init 的接入功能；自动静默不等于禁止用户手动接入。用真实 Hook 子进程、打包异 cwd 场景及完整回归闭环验证。本插件可控制 Hook 行为；宿主是否预加载已安装的技能/MCP、或支持项目级加载条件，不由本插件伪造通用 manifest 字段。实际宿主接线须单列验证。

R22：Python 3.11+ 的原生 Hook CLI 必须正确解析 -- 后的消息文件与远端位置参数；原生提交、推送与受管集成在 Linux/macOS 的完整回归均须实测，保留首次失败记录，不将本地 macOS 结果替代 Linux。

## 2026-10-07 增量：统一 .gitflow/ 存储

R23：新项目不创建 Git 元数据下的 gitflow/；state/ 由 Git 本地 exclude 排除。共享状态绑定同一仓库的锚定工作树，支持 linked worktree 和 separate-git-dir，不能把 .git 文件当目录。
R24：旧 activation/origins/journal 保持只读兼容；首次显式 apply（包括重复 init）迁移至 .gitflow/state/，保留旧文件备份且不覆盖冲突数据。读取与预览不迁移、不写 Git 配置。拒绝符号链接和状态冲突；迁移原生 Hook 时只更新可确认由插件生成的脚本，保留用户自定义内容。
R25：使用真实临时 Git 验证共享规则、日志隔离、local 模式 clean、旧数据迁移及迁移后原生门禁；完整回归与发行包校验通过后更新交付证据。
